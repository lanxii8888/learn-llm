# 阶段 2 动手项目：手写 ReAct Agent（研究助理）

> 这是整个路线图里**最关键的阶段**：不用任何框架，从零手写一个 ReAct 循环。
> 目标是真正理解 agent 的骨架，而不是会用某个库。

## 这个 agent 能干什么

一个「研究助理」：给定一个主题，它会**多步规划** —— 先搜索资料、再阅读文档、最后把总结写进文件。全程用真实工具（文件系统读写 + 本地语料搜索），手写 ReAct 循环，无框架。

示例任务（跑起来后直接问）：

```
你 > 帮我调研一下「RAG」这个主题，读相关文档，然后写一份总结到 output/rag总结.md
你 > 语料库里有哪些文档？都讲了什么？
你 > 简单说说 transformer，不用写文件
你 > /trace   查看最近一次完整的 ReAct 过程
你 > exit
```

## 和阶段 1 的区别（为什么要再写一遍循环）

阶段 1 的聊天机器人已经有一个「工具循环」，但它是被动的单步工具调用。阶段 2 把循环升级为**真正的 ReAct**：

| | 阶段 1 | 阶段 2 |
|---|---|---|
| 工具调用 | 单次、点对点（查天气→答） | 多步、有规划（搜索→读→总结） |
| 工具 | 模拟的（假天气、表达式求值） | 真实的（文件系统读写、语料检索） |
| 循环结构 | 简单 while + tool_call | 显式的 Reason → Act → Observe |
| 上下文 | 不处理 | 主动做预算守卫（引出阶段 3） |
| 步数上限 | 有，但没解释为什么 | 讲透为什么必须限步数 |

## 怎么跑起来

> monorepo：依赖统一装在根目录，`.env` 在根目录。阶段 1 已经装过依赖的话，这里不用再装。

```bash
# 根目录（learn-llm/）执行一次即可（如果阶段1已经 pnpm install 过则跳过）
pnpm install

# 启动 stage2
pnpm --filter stage2-react-agent start
# 或
cd stage2/project && pnpm start
```

## 目录结构

```
stage2/project/
├── corpus/            ← 本地语料库，充当「搜索源」（search_docs 检索这些文件）
│   ├── transformer.md
│   ├── rag.md
│   └── agent.md
├── src/
│   ├── config.ts      ← 转发到根目录 config/index.ts（唯一读 .env 的地方）
│   ├── tools.ts       ← 4 个真实工具：搜索/列目录/读文件/写文件
│   ├── agent.ts       ← 核心：手写 ReAct 循环 + 步数上限 + 上下文预算守卫
│   └── index.ts       ← 命令行交互入口
└── output/            ← agent 写总结时的目标目录（运行时自动创建）
```
