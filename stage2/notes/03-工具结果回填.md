# 03 · 工具结果回填

## 核心：结果必须以「对模型友好」的方式回填

工具执行完，结果要作为一条 `tool` 消息追加进历史，模型才能在下一步基于它继续推理。如果这一步做错了，模型会「看不到」工具的结果，或者被结果搞糊涂。

## 三条铁律

### 1. 必须带 tool_call_id 配对

模型可能一次并行调用多个工具。`tool_call_id` 就是「这条结果对应我哪次调用」的身份证。

```ts
this.messages.push({
  role: 'tool',
  tool_call_id: tc.id,   // ← 丢了它，模型不知道结果是谁的
  content: observation,
});
```

### 2. 结果要序列化成字符串

`content` 是字符串。如果你的工具返回的是对象/数组，要 `JSON.stringify`。塞一个原始对象进去，模型读到的是 `[object Object]`，等于没回填。

### 3. 回填内容要「结构化、可读、有来源」

回填不是把函数返回值原样丢回去，而是要思考：**模型下一步要基于这段文字做判断，它需要看到什么？**

本项目 `tools.ts` 里每个工具返回的观察都做了格式化，例如搜索工具返回：

```
【rag.md 第 3 行】
RAG（Retrieval-Augmented Generation...）
```

带文件名 + 行号 + 上下文，模型才知道「这段来自哪份文档」。这就是「让模型不困惑」的关键。

## 错误处理也要「回填」而不是「崩掉」

一个容易被忽略的细节（见 [agent.ts](../project/src/agent.ts)）：工具参数解析失败时，我们不 `throw` 让整个 agent 崩掉，而是回填一条错误观察：

```ts
this.messages.push({
  role: 'tool',
  tool_call_id: tc.id,
  content: '错误：工具参数不是合法 JSON，请重新生成调用参数。',
});
```

这样模型看到错误，会在下一步自己纠正。**把错误变成「观察」，模型才有机会自我修复** —— 这是 agent 可靠性的一个重要思想，阶段 5 会展开。

## 练习

跑起来后 `/trace` 观察：每一步 Action 之后紧跟的那条 Observation，模型有没有在下一步正确「引用」它（比如读到 rag.md 后，总结里用的是文件里的真实内容，而不是编的）。如果模型无视了 Observation，多半是回填格式不够清晰。
