# RAG：检索增强生成

RAG（Retrieval-Augmented Generation，检索增强生成）是一种让大语言模型「先查资料再回答」的技术。

## 要解决的问题

LLM 有两大短板：
1. **知识过时**：训练数据有截止日期，不知道新信息。
2. **容易编造**：对不懂的问题会一本正经地胡说（幻觉，hallucination）。

RAG 的思路：回答前先从外部知识库检索相关文档，把检索到的内容作为上下文一起喂给模型，让模型「有据可依」地回答。

## 工作流程

1. **索引（indexing）**：把文档切块（chunk），用 embedding 模型把每块转成向量，存进向量数据库。
2. **检索（retrieval）**：用户提问 → 把问题也转成向量 → 在向量库里找最相似的 top-k 块。
3. **增强（augmentation）**：把检索到的块拼进 prompt。
4. **生成（generation）**：模型基于这些材料生成回答。

## 关键组件

- **embedding 模型**：把文本映射成向量，语义相近的文本向量也相近。
- **向量数据库**：存储和检索向量（如 FAISS、Milvus、pgvector）。
- **切块策略**：chunk 大小、重叠度直接影响检索质量。

## 常见问题

- 检索不准：该查的没查到，或查到无关内容。
- 引用不当：模型可能引用到不相关片段。
- 上下文窗口：检索结果塞多了会超限，需要在「召回率」和「上下文长度」间权衡。

## 和 agent 的关系

RAG 是 agent 的「长期记忆」的重要实现方式（阶段 3 会讲）。一个研究型 agent 通常会「先检索资料、再阅读、再总结」，RAG 就是它的检索环节。
