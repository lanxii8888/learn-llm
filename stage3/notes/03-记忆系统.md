# 03 · 记忆系统（Memory）

## 两种记忆，别混为一谈

| | 短期记忆 | 长期记忆 |
|---|---|---|
| 载体 | `messages` 数组 | 落盘文件 / 数据库 / 向量库 |
| 生命周期 | 一次进程 | 跨会话 |
| 容量 | 受上下文窗口限制 | 几乎无限（但要维护） |
| 访问方式 | 全量重发 | 按需检索后注入 |
| 淘汰 | 上下文压缩 | 去重、上限、手动清理 |

阶段 2 只有短期记忆，所以你一退出，agent 就「失忆」了。阶段 3 在 [memory.ts](../project/src/memory.ts) 加了长期记忆，并把两者串成一个完整生命周期。

## 长期记忆的完整生命周期

```
写入 → 存储 → 检索 → 注入 → 维护
 ↑                              │
 └──────────── 纠错/删除 ←───────┘
```

### 1. 写入：什么时候记？

本项目有两条写入路径：

- **自动抽取**（主要）：每次回答结束后，用一次**结构化输出**调用，从「任务 + 回答」里提炼「跨会话仍然有用的事实」。见 [agent.ts](../project/src/agent.ts) 的 `extractMemories()`。
- **模型主动记录**：用户明确说「记住……」时，模型调用 `remember` 工具，附带标签。

两条路径都会经过 `memory.add()`，**去重**在那一层统一处理。

为什么需要抽取这一层？因为原始对话里 90% 是一次性细节（「读一下 rag.md」），长期存储价值很低。直接存原始对话，记忆库很快会被噪声淹没。抽取 prompt 明确要求「用户偏好、项目背景、确认过的结论；一次性任务细节不要记」。

代价：**每次回答多一次模型调用**。所以配置里给了 `MEMORY_EXTRACT=off` 开关，评估时也会关掉。

### 2. 存储：一条记忆长什么样

```ts
{ id, text, tags, source, createdAt }
```

`text` 必须是**脱离上下文也能看懂的一句完整话**（工具描述和抽取 prompt 都强调了这一点）。「它」这种代词在记忆里毫无意义。文件在 `data/memory.json`，已 gitignore——它属于用户私有数据，不应进仓库。

### 3. 检索：为什么先不上向量库？

`search()` 用一组**检索词**算命中：

- 英文：长度 ≥2 的单词；
- 中文：2-gram（「长期记忆」→ 长期、期记、记忆）。

命中数除以 query 词数的平方根做归一化，取 top-k。

这是一种**词面匹配**，不是语义检索。但它有三个好处：零依赖、完全可解释、调试时一眼能看出为什么召回这条。用它来讲清「检索 → 注入」的流程足够了。

什么时候必须换向量检索？当记忆量变大、表达差异变大时。比如记忆里写「用户偏好简洁的回答」，用户问「别啰嗦」，词面完全对不上，2-gram 召回为 0，而 embedding 能命中语义。那时就该上向量库（阶段 3 的 RAG 语境）。

### 4. 注入：怎么让模型用上？

检索结果不是单独发一条 system 消息，而是拼进本次的 user 消息里：

```
[相关长期记忆]
- 用户正在做 agent 开发学习项目，目前到阶段3
[/相关长期记忆]

[当前任务]
帮我规划下一步该学什么
```

原因：每次任务各带各的检索结果，不会在历史里无限堆叠；而且它天然属于「这次输入的一部分」，压缩时可随历史一起处理。system prompt 里也明确告诉模型：这是旧信息，事实仍以工具查证为准——防止模型把过期记忆当成真理。

### 5. 维护：记忆不是越多越好

- **去重**：Jaccard 相似度 ≥ 0.85 视为重复，不再新增。自动抽取 + 主动 remember 很容易撞车。
- **上限**：默认 200 条，超出淘汰最旧的。真实系统要按「最近使用 + 重要性」淘汰。
- **纠错**：错误记忆比没有记忆更糟，它会污染之后每一个会话。所以必须能删——本项目提供 `/memory clear`，生产系统需要按条编辑/删除。

## 记忆 vs RAG，到底什么关系

RAG 是「从外部知识库检索资料」，长期记忆是「从自己的历史里检索事实」。机制高度相似：都是**写入 → 检索 → 注入上下文**。区别在于数据来源和写入方式：

- RAG：文档库，离线索引，内容相对稳定；
- 记忆：对话中提炼，在线写入，内容动态且可能错。

所以「长期记忆 = 以 agent 自己为数据源的 RAG」是理解它们关系的一个好角度。

## 常见错误

- 不做抽取直接存原始对话 → 记忆库变垃圾场。
- 存代词或残缺句 → 换一个会话就不知所云。
- 检索结果全量注入 → 又制造了一个上下文问题。
- 只增不删 → 错误记忆永久污染。
- 把记忆当事实来源 → 模型应该仍以工具查证为准。

## 练习

1. 关掉进程再启动，问「你知道我在做什么项目吗」，验证长期记忆跨会话生效。
2. 连续两次说同一件事，观察去重是否阻止重复写入。
3. 故意记一条错误信息，再用 `/memory clear` 删掉，体会「可纠正性」为什么是记忆系统的必需项。
4. 把 `search()` 的 2-gram 换成英文单词匹配，用中文查询，观察召回如何失效——这就是为什么中文场景需要更合适的检索方案。
